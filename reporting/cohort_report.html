Given a question and a parsed PDF, return a small set of original pages that contains the evidence. The answer-writing step comes later.

JEV DFSJEV ranks ToC branches. Code explores them depth first, checks page windows and keeps evidence. If it is insufficient, continue or backtrack.
Exhaustive JEVPut every nonempty page into bounded windows. Check up to eight windows concurrently, then select evidence.
Sol agentSol sees the ToC, chooses where to read, receives the pages and selects evidence. It controls navigation and stopping.

How this comparison was run
  • Four PDFs from PageIndex-OSS-Benchmark: Amazon (85 pages), Best Buy (75), Activision Blizzard (198), and the coffee manual (108). Their original extracted ToCs are unchanged.
  • Eight questions are from the smaller OSS benchmark; twelve further existing labels come from its source dataset, MMLongBench-Doc-V2. All have annotated evidence pages. Additional questions include tables and evidence across pages.
  • Every approach gets the same text, ToC and 8-page / 12k-token read and output limits. JEV neighbors count toward the read limit. No summaries are generated for retrieval.
  • JEV asks one judgment per candidate page, read with its neighbors as context, in one request per page window. Only the judged page can be returned; a neighbor is returned only on its own score.
  • JEV DFS keeps every branch recoverable and stops once JEV judges that nothing the question needs is missing from the selected pages (score ≥ 0.85). Exhaustive checks every page. Sol uses the same tree through its own navigation actions and has no JEV helper.
  • Every approach sends one request at a time. There is no parallelism, so time per question follows the work done rather than scheduling.
  • Each JEV approach ran every question three times, four questions at a time; Sol ran one to two times per question, one question at a time, in an earlier session. Within a question, every approach sends one request at a time. The timer ends before gold scoring; preprocessing and downstream answering are excluded.
  • Answer supported: the returned pages contain every annotated page, or a reviewed alternative page set that gives the same gold answer. No answer is generated. Page recall is the fraction of annotated pages returned; other pages may contain repeated evidence. All questions here are answerable; absence detection and image-only evidence are not evaluated.
  • This was not an isolated benchmark host: local report development and validation occurred during collection.
  • This is a convenience cohort with three financial reports and one manual. No human baseline, random-navigation baseline, region control or network/server timing split was measured.
  • Client handling is part of these implementations: JEV reuses a client within a run; Sol creates an OpenAI client for each turn. This compares complete retrieval policies, not intrinsic model inference speed.
  • Exact SDK requests, parsed results, input hashes, model versions and matching source snippets are embedded. Every attempt remains visible, including errors and limit stops.
